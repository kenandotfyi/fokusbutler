# TodoistCompanion module

Action.php owns page-save synchronization, completion/status AJAX, and the local task registry. Syntax.php renders `{{todoistcompanion>Task|id=abcd1234}}` and `~~TODOS~~`. Admin.php owns connection configuration and renders the same live Todoist project list as `~~TODOS~~`. script.js and style.css own the task UI and toolbar dialog.

Credentials resolve from `/run/secrets/todoist_api_token`, then `TODOIST_API_TOKEN`, then `todoist_api_token` under Butler configuration. Runtime state uses `<metadir>/fokusbutler/todoist`. AJAX endpoints use the `fokusbutler_todoist_` prefix. Disabling the module stops synchronization and leaves task text readable.

This is an internal Fokus Butler module, not a separately installable DokuWiki plugin. See [the companion README](../../README.md) for installation, module switches, asset loading, and development checks.

## Todoist project list

`~~TODOS~~` displays every task in the configured Todoist project (default: **Wiki**), including recently completed tasks confirmed by Todoist (the last 89 days). Todoist is authoritative: deleted tasks and tasks moved out of the project disappear after the next successful refresh. Wiki task records supply backlinks only and never add tasks to this list. The list no longer scans wiki pages for task syntax, so removing `{{todoistcompanion>...}}` from a page does not remove that task from the aggregate. Add an idea to the Wiki project from any Todoist client; the list refreshes while open. Entries show their description as plain text, due date/time and timezone when supplied, recurrence, deadline, labels, creation date, and a linked Todoist logo. Wiki-created tasks also link back to their source page when its task registry entry and read permission are available, with the page's first heading as the link name and its normal DokuWiki preview. Due and added timestamps sit below the task name in the secondary text color at 60% opacity as `YY-MM-DD HH:MM`; date-only due dates omit the time. Explicit timestamp offsets are converted to the task timezone for due dates, or the server timezone for added dates. Priority is hidden. Markdown in descriptions remains readable source text.

Reads use Todoist's [API v1](https://developer.todoist.com/api/v1/) with project filtering and cursor pagination. The wiki renders first, then loads the project list through AJAX so Todoist response time does not delay the page refresh. A single versioned `incoming.json` snapshot powers the list and the Fokus statusbar; cached wiki syntax is never added to the count. The snapshot is scoped to the configured token and project, with refreshes serialized across requests and throttled to once every 20 seconds. Old `history.json` and `completion.json` files are ignored automatically, so deploying the fix does not require manual cache deletion. Each successful active-task refresh replaces the active snapshot, including a valid empty result. A failed or partial active refresh preserves the last good data and labels it cached; without a confirmed snapshot, the statusbar shows “Todoist unavailable.” Completed tasks are reconciled from a full bounded 89-day remote window rather than accumulated indefinitely. If only that endpoint fails, current active tasks still update and the list warns that completed history could not refresh. Deleted/tombstoned rows are excluded. Opening a list never creates a project, and ambiguous duplicate project names produce an error rather than selecting an arbitrary project.

Completing a task in DokuWiki invalidates the shared snapshot immediately; confirmed non-recurring completions remain completed if the next read fails. Recurring/reopened active tasks take precedence over completed history. Visible lists refresh every 20 seconds, when the browser regains focus, and after completing a task; list changes refresh the statusbar too. Failed AJAX refreshes retain existing rows with a visible warning. Page-embedded task references still check missing-task responses independently, with automatic source cleanup subject to edit permission, CSRF checks, and page locks.

Todoist project contents require a logged-in user with read access to a page containing `~~TODOS~~`; administrators can also view the list in the TodoistCompanion settings panel. All such readers share the configured account's Wiki project; put the list on an appropriately restricted page in a multi-user wiki. Anonymous readers cannot see project tasks. Parser caching is disabled for task lists. Edit permission on the list page plus a valid CSRF token allows completing an active task in Todoist; administrators can complete from the settings panel. The task's current project and active status are checked again before completion; recurring tasks refresh on the next view. Project tasks do not alter page source or become wiki task syntax. Title/description editing remains in Todoist.

Run isolated Todoist snapshot/reconciliation checks with `php tests/todoist.php` and `node tests/todoist-list.cjs`; these use mocked API responses and temporary metadata only.
