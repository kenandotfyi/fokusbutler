# TodoistCompanion module

Action.php owns page-save synchronization, completion/status AJAX, and the local task registry. Syntax.php renders `{{todoistcompanion>Task|id=abcd1234}}` and `~~TODOS~~`. Admin.php owns connection configuration and the all-task list. script.js and style.css own the task UI and toolbar dialog.

Credentials resolve from `/run/secrets/todoist_api_token`, then `TODOIST_API_TOKEN`, then `todoist_api_token` under Butler configuration. Runtime state uses `<metadir>/fokusbutler/todoist`. AJAX endpoints use the `fokusbutler_todoist_` prefix. Disabling the module stops synchronization and leaves task text readable.

This is an internal Fokus Butler module, not a separately installable DokuWiki plugin. See [the companion README](../../README.md) for installation, module switches, asset loading, and development checks.

## Incoming ideas from Todoist

`~~TODOS~~` displays active and recently completed tasks created directly in the configured Todoist project (default: **Wiki**). The existing start page already contains this list. Add an idea to that project from any Todoist client; reopen the wiki list to see it. Incoming entries show their description as plain text, due date/time and timezone when supplied, recurrence, deadline, labels, creation date, and a linked Todoist logo. Due and added timestamps sit below the task name in the secondary text color at 60% opacity as `YY-MM-DD HH:MM`; date-only due dates omit the time. Explicit timestamp offsets are converted to the task timezone for due dates, or the server timezone for added dates. Priority is hidden. Markdown in descriptions remains readable source text.

Reads use Todoist's [API v1](https://developer.todoist.com/api/v1/) with project filtering and cursor pagination. The wiki renders first, then loads the incoming project list through AJAX so Todoist response time does not delay the page refresh. The server keeps a separate `incoming.json` snapshot under the module's metadata directory and refreshes it at most every 20 seconds while the wiki list is open. Failed or partial refreshes retain the last successful snapshot and show a warning. Opening a list never creates a project. Completion from Todoist is reflected as checked for every wiki-linked task and imported task; reopening a task in Todoist clears its checked state. Wiki-linked tasks sync when task status is requested. Open wiki pages poll task status and refresh the incoming list every 20 seconds while visible, and the server caches completion checks for 20 seconds. Wiki-linked tasks remain in the wiki list and are excluded from incoming entries using the existing registry.

Incoming personal tasks require a logged-in user with read access to a page containing `~~TODOS~~`. All such readers share the configured account's Wiki project; put the list on an appropriately restricted page in a multi-user wiki. Anonymous readers cannot see incoming tasks. Parser caching is disabled for task lists. Edit permission on the list page plus a valid CSRF token allows completing an incoming task in Todoist. The task's current project and active status are checked again before completion; recurring tasks refresh on the next view. Incoming tasks do not alter page source or become wiki task syntax. Title/description editing remains in Todoist.

Run isolated incoming-sync checks with `php tests/todoist.php`; these use mocked API responses and temporary metadata only.
